## Важный контекст

- Production: `интер.вмалмыже.рф`, сервис `trener` на `:3007`; deploy автоматически после зелёного CI на `main`. Миграционные PR — по [`docs/migrations.md`](migrations.md): накат ДО мержа, авто-деплой падает на guard (ожидаемо), код доезжает ручным «Deploy to production».
- Визуальная приёмка: использовать Edge через установленное расширение Codex. Для локального dev на PC40 Edge надёжно открывает `http://127.0.0.1:<порт>`; `localhost` в этой сессии давал таймаут навигации.
- **Красный `main` тихо останавливает прод.** Автодеплой висит на `workflow_run` от CI: чужой красный → deploy `skipped`, без письма.
- **`NEXT_PUBLIC_*` запекаются на CI-сборке** — правкой `/etc/trener/trener.env` не меняются. Поэтому публичные значения (контакты продавца, ID Метрики) живут константами в репо.
- 🆕 **Внешний скрипт отдался с 200 ≠ интеграция работает.** Счётчик Метрики без
  `?id=<номер>` в src грузится, выполняется (`Ya.Metrika2` определён) — и не
  инициализируется: очередь `window.ym.a` не разбирается, ни одного
  `mc.yandex.ru/watch/...` не уходит. Снаружи всё зелено: HTTP 200, ноль ошибок в
  консоли, отрисованный информер — и вечный ноль визитов. **Приёмка интеграции —
  только по подтверждению в панели самого сервиса**, и это условие надо записывать
  в план ДО работ (у нас было записано — потому и поймали за час, а не за месяц).
- 🆕 **Метрика: punycode в фильтр адресов больше не вносится.** Кабинет отвечает
  «Неверный формат URL» на любой `xn--`-адрес (латинский `example.com` в то же поле
  проходит — дело именно в punycode). G136 в этой части устарел; Метрика нормализует
  IDN сама, `page-url` в реальных хитах приходит punycode-хостом и принимается с 200
  при фильтре с одним кириллическим написанием.
- 🆕 **`/start` разворачивается ДО того, как сам синхронизирует репо** — и потому
  может выполняться по отменённой инструкции. Поймано на себе: сессия стартовала с
  отставанием на 15 коммитов и сделала запрещённый `pull` в чужой репо по тексту,
  который накануне отменил PR #117. Лечение — шаг 1b в `/start`: после `pull`
  перечитать файл команды; файл всегда прав.
- **knip локально на rmz4val падает по памяти** — гейт мёртвого кода судить по CI. Заводя хелпер «на будущее», сразу проверяй, что он используется, иначе CI красный.
- **Ветка, отпочкованная от другой ветки, конфликтует после squash-мержа родителя.** Лечится `git format-patch` + новая ветка от `main` (force-push в этом окружении запрещён).
- ⚠️ **`git checkout -- <файл>` сносит несохранённую работу целиком.** За сессию так
  потерялась только что написанная функция: откатывал временную мутацию теста, а
  вместе с ней ушла и правка. Для временных мутаций — точечный обратный `sed`, а не
  откат файла к HEAD.
- Юридический контур: реквизиты филиала + подпись договора — технический гейт, а не памятка (D-016).
