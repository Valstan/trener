## Важный контекст

- Production: `интер.вмалмыже.рф`; deploy автоматически после зелёного CI на `main`.
  Миграционные PR — по [`docs/migrations.md`](migrations.md): накат ДО мержа, авто-деплой
  падает на guard (ожидаемо), код доезжает ручным «Deploy to production».
- 🆕 **D-038: инфра-детали бокса в репо не кладём** — правило и исключения в `AGENTS.md`
  («Публичный репозиторий — recon-поверхность»), гейт `scripts/recon-lint.sh` (generic-паттерны,
  без реальных значений). Значения: GitHub secrets (`PROD_SSH_HOST`, `PROD_SSH_USER`,
  `SSH_PRIVATE_KEY`), `EnvironmentFile` бокса (`PORT`, `SECRETS_MANAGER_URL`, секреты),
  локальный `~/.ssh/config`. Handoff — живой документ: порт за прокси и ssh-алиас сюда не писать.
- 🆕 **Required checks на `main` = только `web-quality`** (снято Мозгом 17.08). Check
  `gitleaks` (`secret-scan.yml`) **не блокирует мерж** — попросил Мозга добавить письмом
  23.08 (защита ветки — его зона, постулат 34). Новые гейты поэтому кладём **шагами внутрь**
  `web-quality` (так сделан recon-lint), а не отдельными джобами.
- 🆕 **Юниты в `deploy/systemd/` — шаблоны**: `__DEPLOY_USER__`/`__DEPLOY_HOME__` рендерит
  remote-скрипт `deploy-prod.yml`; ручная установка — `sed` из комментария в `trener.service`.
  `PORT` только в `trener.env` бокса: убрать его оттуда = сервис сядет на дефолтный порт Next.
- 🆕 **Vault-клиент — аварийный путь** (`secretsBootstrap`): комната — копия, источник —
  env бокса; `SECRETS_MANAGER_URL` теперь обязателен (лежит в `secrets-token.env`). Мина #171
  не применима; ретраи не заводить — повтор даёт `Restart=on-failure`.
- 🆕 **gitleaks: свои правила в `.gitleaks.toml`** (URL БД с паролем; ENV-форма `*_PASS=`).
  Новый класс секрета → мутация одноразовой веткой (образец: PR #150), а не доверие дефолту.
- 🆕 **`isOwner` vs `isFullOwner` в роутах = граница демо/прод** (#152): демо-владелец имеет
  roles:['owner'], поэтому `isOwner(user)`=true. В server-mediated роутах для скоупа филиала/группы
  использовать `lib/groupScope.staffCanManageGroup` (групповые) или `isFullOwner` (сетевые owner-only);
  `isOwner` оставлять только как роль-гейт (`isCoach||isOwner`) и метку authorRole. Демо → live
  протекает через overrideAccess:true (create-access с Where не фильтрует, G211) — проверять каждый
  новый роут «а что делает демо-владелец». **И afterChange-хуки тоже** (#155): фан-аут с
  ГЛОБАЛЬНЫМ списком получателей (`roles:['owner']` без фильтра демо) шлёт живым, даже когда
  запись скоуплена — `sendPushToUser` режет только адресата-демо. Демо-действие глушить у
  источника по `doc.demoGuest`.
- 🆕 **Паспорт (ADR-0012) работает**: `passport-probe.yml` (dispatch только с `main` —
  сервер пинит субъект `^repo:…:ref:refs/heads/(main|master)$`, с ветки 401 by design).
  Адрес комнаты — secret `VAULT_BASE_URL`. Токен НЕ кладём в `$GITHUB_ENV` (рецепт спеки
  так делает — отдал бы его всем шагам job'а); самоотзыв на `trap … EXIT INT TERM`, иначе
  под `set -e` он недостижим при сбое. Понадобится реальный pull секретов в CI — брать
  токен этим шагом и держать в одном шаге.
- 🆕 **Смоук деплоя — `scripts/smoke.sh <base-url>`**, гоняется по публичному адресу из
  `NEXT_PUBLIC_SERVER_URL`. Новую публичную страницу добавлять туда же строкой `check_page`.
  Правишь скрипт — прогоняй фикстурами (`MODE=good|no-marker|no-css-link|css-404|page-500|health-bad`),
  а не только «на живом»: живой прод зелёный и у декоративного гейта.
- 🆕 **Функцию, которая ставит глобальные переменные, нельзя звать через `$(...)`** —
  подстановка это подоболочка, присваивания не доезжают. Ловится только прогоном с
  заведомо исправным входом: если «сломано всё», подозревай тест, а не предмет.
- 🆕 **Лог CI — тоже recon-канал** (D-038): маска GitHub ловит только точное значение
  секрета, поэтому страница прокси (502/504) с голым хостнеймом проходит мимо неё. Тело
  чужого ответа в лог не печатать — только поля, извлечённые по имени, и обезвреживать `::`
  (stdout раннера парсится на workflow-команды).
- 🆕 **Письма Мозга с `ack: none` всё равно стоит закрывать `ref:`** — три письма 15.08
  висели у него «проект писал, но неясно о чём» до 23.08.
- **Красный `main` тихо останавливает прод.** Автодеплой висит на `workflow_run` от CI:
  чужой красный → deploy `skipped`, без письма.
- **`NEXT_PUBLIC_*` запекаются на CI-сборке** — правкой env бокса не меняются; публичные
  значения (контакты продавца, ID Метрики) живут константами в репо.
- **Внешний скрипт отдался с 200 ≠ интеграция работает** (Метрика без `?id=`): приёмка
  интеграции — только по подтверждению в панели самого сервиса, условие писать в план ДО работ.
- **Метрика: punycode в фильтр адресов не вносится** («Неверный формат URL»); G136 в этой
  части устарел.
- **`/start` разворачивается ДО синхры репо** — после `pull` перечитать файл команды (шаг 1b).
- **knip локально на rmz4val падает по памяти** — гейт мёртвого кода судить по CI.
- **Ветка от ветки конфликтует после squash-мержа родителя** — `git format-patch` + новая
  ветка от `main`.
- ⚠️ **`git checkout -- <файл>` сносит несохранённую работу целиком** — для временных
  мутаций точечный обратный `sed`.
- Юридический контур: реквизиты филиала + подпись договора — технический гейт (D-016).
