## Следующий шаг

Два шага требуют **владельца** (оба в `PENDING_FOLLOWUPS.md`): завести счётчик Метрики
и утвердить цены подписки. Пока их нет — следующая независимая нить:

**Живая приёмка по ролям на мобильной ширине.** Прогнать руками полный сценарий:
регистрация → заявка → подтверждение → группа → расписание+RSVP → чат → оплата →
согласие/отзыв, в светлой и тёмной теме, роли ребёнка/родителя/тренера/владельца.
Сессия закрывала разрывы по коду и проверяла их curl'ом и юнитами; браузерная панель
в этой сессии не отображалась, поэтому визуальная приёмка не делалась.

Кандидаты на следующую нить после приёмки: посещаемость (факт явки — отсутствует как
класс, только RSVP-намерение); серии тренировок как сущность (массовая правка/отмена);
живое обновление чата (сейчас только `router.refresh()` после своей отправки).

## Важный контекст

- Production: `интер.вмалмыже.рф`, сервис `trener` на `:3007`; deploy автоматически после зелёного CI на `main`. Миграционные PR — по [`docs/migrations.md`](migrations.md): накат ДО мержа, авто-деплой падает на guard (ожидаемо), код доезжает ручным «Deploy to production».
- **Красный `main` тихо останавливает прод.** Автодеплой висит на `workflow_run` от CI: чужой красный → deploy `skipped`, без письма.
- **`NEXT_PUBLIC_*` запекаются на CI-сборке** — правкой `/etc/trener/trener.env` не меняются. Поэтому публичные значения (контакты продавца, ID Метрики) живут константами в репо.
- **knip локально на rmz4val падает по памяти** — гейт мёртвого кода судить по CI. За сессию он трижды ловил неиспользуемый экспорт: заводя хелпер «на будущее», сразу проверяй, что он используется, иначе CI красный.
- **Ветка, отпочкованная от другой ветки, конфликтует после squash-мержа родителя.** Дважды за сессию: лечится `git format-patch` + новая ветка от `main` (force-push в этом окружении запрещён).
- Юридический контур: реквизиты филиала + подпись договора — теперь технический гейт, а не памятка (D-016).
