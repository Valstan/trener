# Видение v2: многофилиальная платформа футбольной школы

> Диктовка владельца 2026-07-26, структурирована AI-сессией. Статус: **ЧЕРНОВИК —
> зафиксированное видение, НЕ план работ.** Открытые вопросы — в конце; план вех
> (M5+) — после ответов владельца.

## 1. Суть поворота

Сейчас trener — приложение одной школы (один «филиал» де-факто). Становится —
**одна платформа для всей сети школы с филиалами по разным городам**.

## 2. Структура и роли

### Верхний уровень: филиалы

- Приложение одно, но **филиал — граница видимости**: участник живёт в одном
  филиале и видит только его (мероприятия, чаты, расписание, матчи, оплаты, медиа).
- Филиал к филиалу не заглядывает. Тренеры чужих филиалов не видят.

### 4 уровня доступа

| Роль | Что может |
|---|---|
| **Владелец** | «Бог»: видит все филиалы, переключается между ними, создаёт филиалы, назначает администраторов/тренеров филиалов, назначает других владельцев (их может быть 2–3+). Общие объявления/баннеры: сразу во все филиалы или выборочно в несколько (пример: сборы, «битва городов» в Самаре). |
| **Тренер** | Руководит своим филиалом: расписания тренировок и матчей, фотогалереи, ветки чатов, добавление/удаление пользователей (точный объём прав — вопрос §7). |
| **Родитель** | Видит свой филиал: расписания, объявления, чаты (взрослая комната), оплаты своего ребёнка, медиа. |
| **Ребёнок** | Отдельная роль. Детская комната чатов (под присмотром), контент филиала. ⚠️ большой 152-ФЗ-вопрос — §7. |

- У владельцев может быть «бухгалтер» — кто-то, кто ведёт оплату и управляет
  составом чатов (возможно отдельная под-роль, вопрос §7).
- Тренеру можно дать права шире только повышением до владельца.

### Модерация входа (новое правило онбординга)

Новый зарегистрировавшийся видит **только главную с карточками разделов — всё
заблокировано**. Доступ открывается только после того, как владелец/администратор
подтвердит участника и выдаст роль (владелец/тренер/родитель/ребёнок).

## 3. Разделы приложения (главная = карточки-плашки)

1. **Матчи** — прошедшие (с результатами) и расписание будущих (соревнования:
   когда, во сколько, где). Ведут тренеры, смотрят родители.
2. **Расписание тренировок** — уже есть (M2/наработки #66).
3. **Чаты. Комнаты:**
   - **Взрослая комната** — тренеры + родители; дети попасть не могут.
   - **Детская комната** — дети между собой, под присмотром родителей/тренеров.
   - Внутри комнаты — несколько тематических чатов (напр. «едем на соревнования»).
4. **Оплата** (отдельный раздел, чтобы про оплату не писали в чатах):
   - Таблица по детям: срок абонемента (с даты — по дату), оплатил/не оплатил/
     переплата, сумма к оплате, скоро ли срок.
   - Ведёт бухгалтер/владелец. Родитель находит своего ребёнка, видит сроки.
   - **Помощник оплаты**: QR-код / ссылка на форму оплаты (желательно с
     предзаполненными реквизитами) / копирование реквизитов в буфер + пошаговая
     инструкция как платить. ⚠️ Мы НЕ проводим платежи сами — только помощник.
5. **Фотогалерея** — по папкам-событиям: «в этот день был матч, счёт такой-то» +
   фото/видео. **Родители сами добавляют медиа с телефона.**
6. **Объявления/баннеры** — филиальные (тренер) и общесетевые (владелец, во все
   или выборочно филиалы; баннер на главной).

## 4. Хранение медиа — Яндекс S3

Фото/видео — не на прод-сервере, а в **Yandex Object Storage (S3)**, как сделано
у Sabantuy (и, вероятно, у «казанской»). Загрузка родителем с телефона → сразу в
облако. **Взять реализацию у Sabantuy — посмотреть в sibling-репо (ADR-0007
разрешает прямое read-only чтение).**

## 5. Авторизация — решение владельца (2026-07-26, предварительное)

Раз филиалы по разным городам, вход через «вход.вмалмыже.рф» для всех — плохо
(региональная привязка в названии). Склоняется к: **своя отдельная авторизация
этого приложения, без указания на регионы** — вход через ВКонтакте + позже другие
способы. Вариант «малмыжанам — ЕСА, остальным — своя» рассматривался и отклонён
как путаница (но финального решения нет — §7).

Примечание сессии: код OIDC-клиента (`lib/auth/oidc.ts`) провайдер-независим —
«своя авторизация через VK» = VK ID напрямую вместо Радара, большая часть кода
переиспользуется. Живой Радар-round-trip сейчас в любом случае заблокирован 500-кой
на их стороне (письмо Мозгу 2026-07-26).

## 6. Что из этого уже было в планах (kickoff §8 «Этап 2»)

Поездки/соревнования ✓ (→ матчи+объявления), медиа #024 ✓ (→ S3-галереи), оплаты ✓
(→ раздел оплаты), праздники/поздравления, «что взять/форма одежды», экспорт
календаря — владелец не упоминал, но из планов не выкинуты. Полный чат M4 уже
построен — комнаты/ветки = его развитие.

## 7. Решения владельца (2026-07-26)

1. **Авторизация — полностью своя: VK ID напрямую**, без вход.вмалмыже.рф
   (нейтрально для филиалов из других городов). Код OIDC переиспользуем. Отказ от
   Радара проговорить с Мозгом письмом — мы его референс-клиент.
2. **Роль «ребёнок» — отложена отдельной вехой** после юр-проработки 152-ФЗ
   (согласие представителя на аккаунт, модерация детской комнаты, VK ID 14+).
   v2 стартует с ролями владелец/тренер/родитель.
3. **Текущая школа = «филиал №1 (Малмыж)»**, все существующие данные переносятся
   в него миграцией.
4. **«Бухгалтер» — не отдельная роль**, это человек с ролью владельца.

## 8. Открытые вопросы (не блокируют старт, решить по ходу)

1. **Детские медиа** (галереи): согласие на публикацию изображения ребёнка
   (ст. 152.1 ГК) — от каждого родителя? Видимость строго внутри филиала?
2. **Права тренера на пользователей:** добавлять/удалять участников — тренер или

3. **Оплата:** подтвердить «табличка + помощник, деньги не проводим»; реквизиты —
   у каждого филиала свои?
4. **Фаза:** закрытое тестирование остаётся на время постройки v2 (предположение).

## 9. Черновой план вех v2 (уточнится при проектировании)

- **M5 — филиалы + владелец.** Коллекция Branches, `branch`-скоупинг всех
  существующих коллекций + пересчёт access-правил, роль owner с переключателем
  филиала, миграция данных в «филиал №1», модерация входа (новичок заблокирован
  до подтверждения и выдачи роли).
- **M6 — своя авторизация.** VK ID напрямую (переиспользование `lib/auth/oidc.ts`),
  magic-link остаётся fallback'ом. Письмо Мозгу об уходе с Радара — до начала.
- **M7 — главная-карточки + общесетевые объявления/баннеры** (во все или
  выборочные филиалы) + матчи-расписание соревнований.
- **M8 — оплата.** Таблица абонементов по детям + помощник оплаты
  (QR/ссылка/копирование реквизитов + инструкция).
- **M9 — комнаты чатов.** Взрослая комната поверх M4-чата, тематические ветки.
  (Детская комната — после юр-проработки роли «ребёнок».)
- **M10 — S3-медиа-галереи.** Yandex Object Storage по образцу Sabantuy, загрузка
  родителями, папки-события с результатом матча. Гейт: юр-вопрос детских фото (§8.1).
- **M11 (отложено) — роль «ребёнок» + детская комната.** После юр-проработки.
