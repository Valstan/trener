# Онбординг школы: оператор ПДн и поручение обработки

> Рабочая инженерная памятка, не юридическая консультация. Шаблон договора и текст
> согласия нужно один раз проверить у специалиста до первого платящего клиента.

Оператором персональных данных является подключаемая школа. Платформа обрабатывает
данные по её поручению (ст. 6 ч. 3 152-ФЗ).

## До приглашения родителей

1. Заполнить в карточке филиала полное наименование/ФИО ИП, форму, ИНН, почтовый
   адрес, email и телефон для обращений по персональным данным.
2. Подписать со школой договор поручения и поставить дату в карточке филиала. В
   договоре перечислить цели, категории данных, действия, конфиденциальность, меры
   защиты и судьбу данных после расторжения.
3. Школа самостоятельно проверяет обязанность и подаёт уведомление в Роскомнадзор.
   После подачи зафиксировать дату в карточке филиала; платформа уведомление за школу
   не подаёт.
4. Открыть `/privacy`, выбрать филиал и проверить реквизиты. Плашка «Тестовый контур»
   исчезает только когда обязательные реквизиты заполнены и договор подписан.
5. Проверить отдельный экран согласия родителя: оператор — его филиал, платформа
   названа обработчиком по поручению.

## Запрос родителя

Родитель обращается в школу-оператор. Школа идентифицирует заявителя и направляет
платформе поручение на выгрузку, уточнение или удаление данных конкретного человека.
Выгрузка выполняется техническим сотрудником по подтверждённому поручению школы:
`SUBJECT_EMAIL=... pnpm -C web payload run ./src/scripts/export-data-subject.ts`.
Результат печатается в stdout и передаётся школе по согласованному защищённому каналу.
Удаление выполняется в Payload Admin удалением пользователя: `cleanupUserRelations`
каскадно удаляет согласия, устройства, уведомления, RSVP и личные вопросы; карточки
детей отвязываются и при требовании полного удаления удаляются администратором школы.
Основание, объём и результат операции фиксируются во внутреннем журнале обращения.
