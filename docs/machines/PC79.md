## Гейты (сверено 14.09, все зелёные)

`cd web && corepack pnpm lint / typecheck / test -- --run / deadcode / build`, в корне
`bash scripts/recon-lint.sh`. Тестов 402/402.

- ⚠️ **`gh` таймаутится так же, как на rmz4val.** Сначала я записал сюда «отвечает
  стабильно» — за первые два часа сессии ни одного сбоя. К концу той же сессии словил
  `Post "https://api.github.com/graphql": … wsarecv: An established connection was aborted`,
  причём сразу на двух вызовах подряд, при живом push/pull по HTTPS. То есть симптом
  идентичен rmz4val и **отсутствие сбоев в начале сессии ничего не доказывает** — это
  перемежающийся отказ, а не свойство машины. Длинные цепочки (`pr checks` → `run watch`
  → `pr merge`) гонять циклом с ретраем, а не одним вызовом.

## Миграции локально (сверено 14.09)

Полный прогон на чистой БД работает и стоит дёшево:

```
NODE_ENV=production corepack pnpm migrate        # накатить все миграции
NODE_ENV=production corepack pnpm migrate:create <slug>   # проверить дрейф схемы
```

`NODE_ENV=production` здесь важен: без него `push: true` синхронизирует схему сам и
маскирует расхождение, которое ищешь. 14.09 так проверено, что payload 3.89 миграций не
требует (`No schema changes detected`) — это честнее, чем принимать бамп деплоем.
