## Миграции локально (сверено 14.09)

Полный прогон на чистой БД работает и стоит дёшево:

```
NODE_ENV=production corepack pnpm migrate        # накатить все миграции
NODE_ENV=production corepack pnpm migrate:create <slug>   # проверить дрейф схемы
```

`NODE_ENV=production` здесь важен: без него `push: true` синхронизирует схему сам и
маскирует расхождение, которое ищешь. 14.09 так проверено, что payload 3.89 миграций не
требует (`No schema changes detected`) — это честнее, чем принимать бамп деплоем.

## Доступ к прод-боксу (заведён 14.09)

Есть: отдельный ключ `~/.ssh/id_ed25519_trener` + алиас в `~/.ssh/config`, вход под
админским пользователем с `sudo`. **Значения (алиас, хост, порт, пользователь) — в
`~/.ssh/config` и только там**: D-038, публичный репозиторий — recon-поверхность.
Отдельный ключ, а не переиспользование соседского, чтобы отзывать независимо; на боксе
он лежит в `authorized_keys` админского пользователя, бэкап прежнего файла — рядом с
суффиксом `.bak-before-trener-key`.

Зачем это нужно и почему раньше было больно: до 14.09 доступа с этой машины не было, и
строку отчёта Мозгу про журнал прода закрыть было нечем — приёмка упиралась в «проверю
по косвенным признакам». Что теперь снимается напрямую:

```
ssh <алиас> 'systemctl show -p ActiveState -p SubState -p NRestarts trener'
ssh <алиас> 'sudo -n journalctl -u trener --since "7 days ago" -o short-iso --no-pager'
```

⚠️ **Журнал юнита хранится ~7 суток** (14.09 самая старая запись была от 07.09). Всё, что
нужно для разбора глубже, снимать сразу, а не «потом посмотрим».

⚠️ Версии пакетов с прода читаются из каталога релиза (`systemctl show -p
WorkingDirectory --value trener`), но там лежит **standalone-трейс**: `next` и `sharp`
видны как отдельные пакеты, а `payload`/`@payloadcms/*`/`drizzle-orm` в `node_modules`
релиза отсутствуют — они вшиты в бандл. Их версию с прода прямым чтением не получить,
только из lockfile сборки.

Длинные цепочки через `ssh` — см. G321 (`ssh host 'bash -s' "$A"` не передаёт argv:
скрипт слать целиком на stdin) и G332 (конвейер внутри строки `ssh` отдаёт код
последнего элемента).

## Машинные грабли

- **`psql`/`createdb` не в PATH** — `command not found` здесь означает «не в PATH», а не
  «не установлено» (в отличие от rmz4val, где это сначала гипотеза «антивирус снёс бинарь»).
- ⚠️ **Встроенная панель: проверено 14.09 сквозной приёмкой, хуже, чем считалось.**
  Панель не отображается — `read_page` отдаёт `Viewport: 0x0`, и любой клик отбивается
  «ref is entirely outside the viewport». Лечится `resize_window` с ЯВНЫМ размером
  (`1280x900`) — после этого координаты появляются. **Но и тогда синтетические клики
  `computer` до React не доходят**: страница их принимает, обработчик не срабатывает,
  форма не отправляется — и выглядит это как «кнопка не работает», а не как проблема
  инструмента. Работает только выполнение JS на странице:
  `element.click()`, `form.requestSubmit()`, а значение в поле — нативным сеттером
  `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` + событие
  `input` (иначе React не видит ввода; `form_input` по той же причине бесполезен).
- ⚠️ **Внешний Chrome 14.09 рвал соединение на каждом втором вызове** («Claude in Chrome
  is not connected»): `navigate` проходил, `javascript_tool` тут же отваливался. Для
  прогона двух ролей одновременно не годится — приёмку вёл последовательно в одной
  панели, переключая роли через `/api/users/login`.
- **Сиды стенда:** `pnpm seed` + `pnpm seed:legal` + **`pnpm seed:demo`** (последний нужен
  для красного пути демо-владельца; без него `/demo` молча висит в `?state=preparing`).
