# Демо-режим D-029 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Публичная демо-витрина: демо-филиал в прод-БД, вход под 5 ролями с лендинга без регистрации, изоляция от живых данных, лимит 5 сущностей, ночной reseed.

**Architecture:** Флаги `branches.isDemo` + `users.demo (saveToJWT)`. Демо-owner/admin едут по СУЩЕСТВУЮЩЕМУ branch-admin-скоупингу M5: `isOwner`-шорткаты в access-решениях меняются на `isFullOwner` (owner && !demo), а `adminBranchId` возвращает `user.branch` и для демо-staff. Вход — существующий `buildAuthCookie`. Reseed — cron-роут по образцу `rsvp-reminders`.

**Tech Stack:** Payload 3 + Next.js (app router), PostgreSQL, vitest.

**Spec:** `docs/superpowers/specs/2026-08-18-demo-mode-design.md`

```ts
// web/src/hooks/demoGuestLimit.ts
import type { CollectionBeforeChangeHook } from 'payload'
import { DEMO_GUEST_LIMIT, DEMO_LIMIT_MESSAGE } from '../lib/demo/constants'

// Лимит витрины D-029: посетитель (демо-юзер) создаёт ≤5 СВОИХ сущностей в разделе.
// Сид пишет через Local API без user → demoGuest=false, богатый сид в лимит не
// упирается. Гонка двух посетителей (6-я вместо 5-й) — не инцидент, reseed ночью.
export const demoGuestLimit: CollectionBeforeChangeHook = async ({ req, operation, data, collection }) => {
  if (operation !== 'create' || !req.user?.demo) return data
  const { totalDocs } = await req.payload.count({
    collection: collection.slug,
    where: { demoGuest: { equals: true } },
    overrideAccess: true,
  })
  if (totalDocs >= DEMO_GUEST_LIMIT) throw new Error(DEMO_LIMIT_MESSAGE)
  return { ...data, demoGuest: true }
}
```

Поле в каждой коллекции: `{ name: 'demoGuest', type: 'checkbox', defaultValue: false, admin: { hidden: true }, access: { create: () => false, update: () => false } }` — ставится ТОЛЬКО хуком (hooks обходят field-access через Local API? нет: хук мутирует `data` до валидации, field-access режет только клиентский ввод — прокомментировать).
