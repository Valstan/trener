## Находка, которую стоит забрать в pool: «валидно по YAML» ≠ «валидно по схеме GitHub»

Записывая пины, я положил `persist-credentials: false` **соседом с `uses:`**, а не внутри
`with:`. GitHub на такой файл отвечает не «неизвестный ключ у шага», а **отвергает файл
целиком**: воркфлоу исчезает из списка, `workflow_dispatch` не работает, и на каждый пуш
прилетает красный прогон 0с, названный **путём файла** вместо `name:` из шапки.

Тот же дефект попал в волну 1 (#189) в `apply-migration.yml` — то есть на `main` с 19:14
**накат Payload-миграций на прод вручную был невозможен**, при том что CI и автодеплой
оставались зелёными: сломан был ровно один файл, и единственный внешний признак — имя
прогона, равное пути. Нашёл это уже на следующей правке того же файла.

Что важно как паттерн (три свойства, по которым беру в pool):

1. **Косвенный признак дефекта виден без логов**: `gh api .../actions/workflows/<file>`
   отдаёт `name`, равный **пути файла**, когда файл невалиден. Имя воркфлоу — бесплатный
   health-check всей CI-конфигурации репозитория; он ловит «воркфлоу исчез» там, где все
   статусы зелёные.
2. **YAML-валидаторы слепы к этому классу**: PyYAML, yamllint и даже проверка дубликатов
   ключей файл пропускают. Нужен валидатор **спецификации GitHub** — `actionlint`
   (`unexpected key "persist-credentials" for step to execute action`), теперь шаг в
   обязательной джобе.
3. **Гейт на «строка есть» — не гейт.** Мой гейт проверял наличие
   `persist-credentials: false`, был зелёным на невалидном файле и **тем же способом внёс
   дефект в другой файл**. Если дефект про место — гейт обязан читать структуру, а не
   искать подстроку. Симптом-почерк, который стоит завести отдельным пунктом: «проверка
   зелёная, а система сломана» = проверялось не то свойство.

Побочная грабля для всех, кто гоняет мутационную приёмку: **`git checkout -- <file>`
возвращает файл к коммиту и забирает несвязанные незакоммиченные правки того же файла** —
в этой сессии это дважды съело работу. Схема: копия файла → мутация → прогон → возврат копии
→ сверка идентичности. Плюс коммит до приёмки.

## Что осталось открытым по #057

Волна 2 (дата 30.10): пуши после отзыва согласия — `sendPushToUser` фильтрует только демо,
`consents` не смотрит ни один из четырёх вызывающих путей; гейт согласия только в UI —

и `environment:` — платформенные настройки GitHub, решение владельца. Токены в URL
(`/auth/verify?token=`, `/join/<token>`) требуют правки nginx, она вне репо.

Ограничение честно зафиксировано: запинненный action всё ещё исполняется с правами джобы,
поэтому запись в workflow требует ревью — это `CODEOWNERS` / branch protection, решение
владельца.
